# 스토리 감사 — 은하아파트 기록

2026-09-08 작업. 8화의 핵심 기록 48개, 일상 글 64개, 프롤로그, 조사 이유, 회신, 해결 해설을 함께 대조했다. 이 문서는 결말과 정답을 포함한다.

## 적용 범위

스토리팀은 `lib/stories.ts`, `lib/narrative.ts`, `lib/world.ts`의 회신 서술을 수정했다. 기록·질문·해설의 변경은 추리팀에 근거와 함께 전달하여 `lib/cases.ts`, `lib/solutions.ts`에서 맞췄다. 일상 글의 날짜 문제는 root에 전달했다.

에피소드·기록·질문 ID, 8개 회신 시각, 공개/비공개 분류, 열람 조건과 저장 형식은 스토리팀이 변경하지 않았다. 80개 공개 글의 누적과 32개 비공개 자료의 회신 경로를 유지한다.

## 감사 기준

- 프롤로그는 이전 조사에서 확인한 사실과 이번 회신의 존재까지만 설명한다. 새 회신을 읽기 전에 그 화의 정답을 알려 주지 않는다.
- 사건이 일어난 시각, 문서가 작성된 시각, 플레이어가 보관본을 받은 시각을 구분한다. 미래 기록을 과거 봉투에 이미 넣어 둔 것으로 설명하지 않는다.
- 카드·계정·방문증이 서로 다르면 먼저 별개의 기록으로 취급한다. 시간이나 옷 색이 같다는 이유로 인물을 합치지 않는다.
- 서윤의 안부 확인과 자료 보존을 동시에 요청한다. 안전 소식을 추리 정답의 대가로 보류하는 인물은 만들지 않는다.
- 돈을 받은 관계, 공지를 처리한 행동, 차단 지시, 실제 차단기 조작, 최종 책임을 각각 입증한다. 한 가지 사실로 나머지를 단정하지 않는다.
- 익명 제보, 전달받은 사본, 당시 목격, 현재 본인 확인, 독립 원본 대조의 출처를 구분한다.

## 시간과 출처의 경계

03.18 사건의 순서는 K17 관리동 정문 입장 20:14 → P042 공용 단말 복사 20:17 → V03 관리동 내부 리더 출발 20:20 → 동문 안뜰 20:21 → 지하 통로 20:23 → 수동 차단 20:24 → 기록실 진입 20:26 → 윤해진에게 통화 20:27 → 최초 인수표 20:30 → 동행 퇴실 20:40이다. 이 일련의 시각은 여러 사람과 여러 기록의 시간선이며, 모두 서윤의 행동이라는 뜻이 아니다. 정문의 인증 입장과 내부 출발 리더는 다른 기록이다.

서윤의 직접 작성 글 21:06과 삭제 21:09는 동행 퇴실 이후다. 당시 글을 올렸다는 사실은 그 시점에 연락 가능한 채널이 있었다는 뜻이다. 이후 연락 상대를 줄인 사정은 7화의 본인 설명으로만 확인한다.

스토리 구조와 접근 인터페이스는 기존 형식을 유지했다. 8개 프롤로그, 8개 조사 흐름, 24개 조사 이유, 8개 회신을 전후 대조했다.

- `npx eslint lib/stories.ts lib/narrative.ts lib/world.ts`: 통과.
- `npx prettier --check lib/stories.ts lib/narrative.ts lib/world.ts docs/STORY_AUDIT.md`: 통과.
- Node/tsx로 실제 모듈을 읽어 8화·24개 질문 연결, 회신 8개의 기존 시각, 공개 80/비공개 32, 조사 발견 기록 ID의 유효성, 비공개 문서 작성일이 회신일보다 늦지 않음을 검증했다.
- 최초 프롤로그·조사 배경·회신·공통 사건 안내에 미래 폐쇄 정보가 없고, 최초 진행에서 폐쇄 공지 6-1을 읽을 수 없음을 검증했다.
- 추리팀 5-6의 목록 작성은 03.19 09:20, 추록 수신은 09:05로 맞춰졌다. 6-2의 N17·민원 삭제·N88 감사행, 7-3의 당시 동행과 03.25 09:50 본인 확인, 7-4의 연락 축소 설명을 본문에서 재확인했다.
- 최종 8개 `intro`와 해결 해설을 프롤로그·회신과 다시 대조했다. 1화 메일의 중립적 표현, 2-3의 정문 입장·공용 단말 로그 출처, 4-1·4-3의 내부 출발 리더, 7화의 별도 안부 회신, 8화의 감사 인수증 수령을 확인했다. 추가 앱 로직 변경은 필요하지 않다.

root의 통합 TypeScript·ESLint·빌드 통과도 확인받았다. 스토리팀의 초기 통합 점검에서 발견한 진행 중 계약·UI 테스트 타입 오류는 담당 팀에 전달되어 해결됐다. 최종 UI 전체 캠페인·HTTP 회귀·게시 검증은 root의 통합 검증 기록을 따른다.
