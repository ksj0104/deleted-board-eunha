# 추리 설계 감사 — 삭제된 게시판 · 은하아파트 기록

검토일: 2026-09-08. 범위: 8화의 24문항, 핵심 기록 48개, 정답·근거 채점, 단계별 힌트, 저장 진행 호환. 일상 기록 64개와 이야기·회신은 담당 팀의 변경본까지 교차 검토했다.

모든 질문 ID, 기록 ID, 정답 문자열과 순서 정답, 두 결말, 저장 `version: 1`을 유지했다. 문서의 정답 문장을 찾고 지정된 ID를 맞히는 방식에 치우친 문제를 계정 연결, 시간 환산, 실제 이체 대조, 리더 해석, 봉인 분류, 실행 대상 해석과 최종 주장 결합으로 고쳤다.

## 채점 계약과 공정성

- `Question.evidenceCount`는 최소 수, `evidenceMax`는 최대 수다. 최대가 없으면 최소와 같다. 빈 초안이나 일부 근거만 고른 초안도 저장할 수 있다. 최소 수는 검증 준비 및 채점에 적용한다.
- `evidenceLimit(question)`과 `evidenceSelectionLabel(question)`을 서버 검증, 질문 준비 상태, UI가 공유한다. 예를 들어 `3~5개`는 완전한 근거를 3개로 제시하거나 관련 보강 자료를 더 연결할 수 있다는 의미다.
- 서버 `Solution.proof`의 모든 사실 요건을 입증해야 한다. 각 요건의 `sources`는 대체 가능한 완전한 문서 조합이며, 조합 내부 문서는 모두 필요하다. 관련 문서를 하나씩 모아 숫자만 채워도 통과하는 판정이 아니다.
- 완전한 입증에 관련 자료를 더 붙여도 상한 안에서는 인정한다. 선택 문서는 모두 해당 사실의 출처 또는 명시된 보강 자료여야 한다. 무관한 일상 글을 추가하는 방식은 인정하지 않는다.
- 답의 정확성과 근거의 충족 여부는 따로 판정한다. 근거가 부족하면 `Feedback[id].evidenceMessage`가 빠진 연결을 설명한다. 정답 ID나 선택지 번호를 알려 주지 않는다.
- 정답·출처 요건·해설은 `lib/solutions.ts`와 서버 엔진에 둔다. 클라이언트의 `lib/game.ts` 참조는 타입 전용이다. `lib/investigation.ts`의 공개 안내에는 서버 정답표를 가져오지 않는다.

다음 표에서 `+`는 함께 필요한 출처, `/`는 대체 가능 출처다. 표의 근거는 대표 경로이며 관련 보강 자료의 모든 조합을 나열하지 않는다.

## 연표와 출처의 교차 정정

1. 개인 초대는 03.17 10:30, 모임 취소는 12:10이다. 초대는 다음 날 약속을 명시하므로 취소의 예외를 확인할 필요가 생긴다.
2. 2-2 영상 판독 작성 시각을 20:35, 2-3 구간 내보내기를 20:31, 2-4 복구까지 포함한 작동 내역을 20:30으로 옮겼다. 문서 작성 시각보다 뒤의 행을 이미 알고 있던 문제를 없앴다. 실제 사건 시각은 바꾸지 않았다.
3. K17 정문 인증 입장, P042의 공용 단말 저장, V03 내부 이동은 서로 다른 사건이다. V03의 서윤 배정은 4화, K17의 조민석 배정과 대면 확인은 7화에서 처음 확보한다. 일반 주민의 복사 이벤트가 관리자 감사 이력 열람 권한을 뜻하지 않는다.
4. E42 최초 인수는 03.18 20:30이다. 03.19에 생성된 원본은 감사보관기의 09:05 수신 추록에 들어 있다. 5-6 목록은 수신 뒤인 09:20, 6-2와 6-5의 기록 시각은 09:05로 맞췄다. Q25 생성 08:58은 본문에 별도로 명시했다.
5. N17의 03.18 전출 본문 교체·게시, P042 민원의 21:09 삭제, N88의 03.19 교체·게시를 분리된 감사행으로 제공했다. 해설이 주장하는 관리 행위에 실제 문서가 대응한다.
6. 7-3은 03.18 20:40 동행과 03.25 09:50 영상 통화 동석을 구분하고 09:58에 작성된다. 7-4의 10:00 본인 설명과 시간이 맞는다. 안부 회신은 별도 안부 요청의 결과이고 원본 보존의 조건이 아니다.
7. 스토리팀이 1·4·5·6·7·8화 회신·조사 동기를 교차 검토했다. 제보 메일, 우편함의 자료 전달, 기록실 당번의 인계, 윤해진의 안부 회신, 정하린의 감사 회신을 서로 다른 역할로 유지했다.
8. root가 보정한 일상 글 댓글 시각을 회귀 테스트에 포함했다. 공개 댓글은 게시글 작성 이후이며, 최초로 접근 가능한 세계 시각 이후의 미래 댓글을 보여 주지 않는다.

## 힌트와 입력

24개 단계 힌트를 모두 검토·수정했다. 마지막 힌트에서도 답, 올바른 선택지 위치, 증거 ID 조합을 직접 제공하지 않는다. 관찰 대상 → 비교 방법 → 빠진 관계를 점검하는 순서다. 조사 안내도 같은 방식으로 바꾸었고, 정렬 문제의 답 순서를 안내 문장에 미리 나열하던 부분을 제거했다.

숫자 입력은 자료 종류를 구분한다. 금액은 `3,000,000원`, `₩3,000,000`, `300만 원`과 전각 숫자를 인정한다. 시간은 완전한 24시간제 `HH:MM`, 보관함은 선행 0을 보존한 네 자리 숫자다. 코드 중간의 `원`, 잘못된 쉼표, 추가 문자열을 지워 정답으로 만드는 방식은 제거했다.

## 저장 호환

정답과 모든 ID가 동일하므로 완료한 회차, 메모, 읽기·수집 상태와 초안을 그대로 유지한다. 과거에 완료한 회차를 새 근거 수 때문에 미완료로 되돌리지 않는다. 미완료 초안의 답도 지우지 않으며 새 기준에 맞는 근거만 보완하면 된다.

최소 수가 늘어난 문항은 `1/meeting` 1→2, `6/deletion` 1→2, `7/sender` 1→2, `8/money` 1→3, `8/purpose` 1→3, `8/remaining` 2→3이다. `5/fragments`는 대조표 하나로 충분하므로 2→1로 줄었다. 기존 5화의 읽기 규칙+대조표 조합도 계속 인정한다.
