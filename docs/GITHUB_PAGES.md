## 실행과 저장

`static/main.tsx`가 기존 게임 화면에 브라우저 저장 클라이언트를 전달한다. 순차 해금, 기록 접근, 답안·근거 판정과 두 결말은 동일한 게임 엔진을 사용한다. 공개판은 `/api/game`이나 로그인 서버에 요청하지 않는다. 공유 이미지, 프롤로그와 게시판 사진은 프로젝트 주소 아래에서 불러온다.

저장은 `eunha.deleted-board.progress.v1` 키의 `localStorage`에 기록한다. 모든 동작은 최신 저장을 읽고 게임 엔진을 적용한 뒤 저장 성공 시에만 성공으로 반환한다. Chrome의 Web Locks는 탭 사이의 요청을 순서대로 처리한다. 저장 함수는 비동기 콜백으로 전달해 실패도 정상적으로 전파하고 잠금을 반환한다. 메모는 브라우저 모드에서 입력 즉시 저장 요청을 보낸다.

손상된 데이터, 미지원 버전, 저장 차단 또는 용량 부족은 기존 값을 보존한 채 오류로 알린다. 초기화는 게임 키만 덮어쓴다. 다른 브라우저·프로필·기기에는 진행이 자동 동기화되지 않는다. 사이트 데이터 삭제나 시크릿 세션 종료 시 기록이 사라질 수 있다. 기존 Sites 주소의 D1 기록은 Pages로 자동 이전되지 않는다.

## 배포

Pages Source는 GitHub Actions이며 `main` 푸시 또는 수동 실행으로 `.github/workflows/pages.yml`을 실행한다. Node 22에서 의존성 설치, 타입·린트·전체 테스트, 정적 빌드와 배포 파일 검사를 통과한 뒤 `dist-pages`를 게시한다. 별도 API 키나 배포 비밀값은 필요하지 않으며 워크플로의 기본 GitHub 토큰과 Pages 권한을 사용한다.

- React 화면: API 요청을 차단한 상태에서 검색·글 열기·수집·근거 선택·답안·메모 입력 후 화면을 다시 생성해 복원 확인.
- `npm run typecheck`, `npm run lint`, `npm run build:pages`, 기존 `npm run build`: 통과.
- `npm run test:pages`: `/deleted-board-eunha/` 하위 주소에서 HTML, CSS/JS, 게임 이미지 14개와 공유 이미지가 정상 응답. 실제 배포용 JavaScript를 JSDOM에서 실행해 프롤로그, 시작, 브라우저 저장과 재접속 복원을 확인. 게임 API 호출 0회.

위 화면 상호작용 검사는 JSDOM을 사용했다. 실제 Chrome의 렌더링·네이티브 모달 제스처를 새로 검증했다는 의미는 아니다. 공개 주소 검사에는 `GAME_PAGES_URL`을 설정한 `npm run test:pages`를 사용하며 실행하는 검증 환경의 저장소에만 기록을 만든다.
