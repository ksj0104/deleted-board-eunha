# 같은 동네를 계속 조사하는 구조

기존 화면은 사건 번호로 게시글을 잘라 매번 14개씩 교체했다. 공개 게시판 안에 사적인 쪽지와 관리자 원본까지 나타났고, 앞에서 본 일상 글은 다음 단계에서 사라졌다. 새 구조는 공간의 일관성과 자료에 접근하게 된 이유를 기준으로 구성한다.

## 주민마당과 받은 자료함

- 주민마당은 공개 글 80개의 누적 공간이다. 시작 시각에는 이미 게시된 17개 글을 읽을 수 있다. 게임 속 시간이 흐를 때 새 글이 추가되며 이전 글·사진·댓글은 그대로 남는다.
- 공개 장부나 공사 안내는 나중 단계의 정답에 쓰이더라도 먼저 발견할 수 있다. 처음에는 평범했던 글을 새 회신과 대조하면서 의미가 달라진다.
- 비공개 자료 32개는 8개의 수신 기록에 속한다. 세탁소에 연락해서 받은 설비 자료, 기록실에서 인계한 봉투, 번호를 복원해 연 보관함의 원본처럼 접근 경위를 명시한다.
- 받은 회신은 누적된다. 출처·받은 시각·원문 시각을 구분하고 보낸 사람이나 첨부 내용으로 검색한다. 공개 자료는 받은 편지에서 주민마당의 원래 글을 찾아보도록 안내한다.
- 세계의 시각은 가장 멀리 진행한 조사로 결정한다. 현재 선택한 사건을 바꾸어도 과거로 돌아가지 않는다. 서버의 기록 접근 검사에도 같은 규칙을 사용한다.
- 다음 단계의 진입은 도착한 회신 확인으로 연결한다. 이미지 프롤로그와 추리 단계는 계속 존재하며, 해결 목표는 별도의 모달에서만 표시한다.

단순히 이전 글까지 모두 보이게 하는 방식은 비공개 문서가 갑자기 게시되는 문제를 남긴다. 모든 자료를 처음부터 공개하는 방식은 회신과 원본 확보의 이유를 없앤다. 공개 공간은 계속 유지하고 비공개 출처를 조사하면서 확보하는 구성이 이 사건에 적합하다고 판단했다.

참고한 [Her Story의 공식 소개](https://www.herstorygame.com/)는 하나의 경찰 영상 데이터베이스를 중심으로 비선형 이야기를 탐색하는 방식을 설명한다. 여기서는 동일한 자료 공간을 다시 읽는다는 원칙을 참고했고, 아파트 주민 게시판과 개인 수신함이라는 별도의 환경으로 구현했다.

## 즉시 반응하는 추리 노트

선택은 로컬 화면에 즉시 반영하고 서버의 승인된 진행 상태 위에 아직 저장 중인 답안을 겹쳐 표시한다. 요청이 대기하는 동안 같은 질문을 다시 수정하면 이전 대기 요청은 보내지 않는다. 이미 전송된 요청의 응답은 더 새로운 선택을 덮어쓰지 못한다.

검증 요청은 저장 대기열 뒤에서 실행한다. 저장이 실패하면 검증을 보내지 않고 선택을 유지한다. 재시도는 현재 선택 전체를 저장하므로 체크를 중복 적용하지 않는다. 저장하지 못한 변경은 브라우저를 닫기 전 경고 대상으로 남는다.
