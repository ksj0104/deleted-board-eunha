# 개발팀 고도화 감사

## 문제와 변경

추리노트는 질문마다 수집한 모든 기록을 펼쳐 놓았다. 캠페인 후반에는 같은 목록이 여러 번 반복되고, 지금 연결한 근거가 긴 목록 속에 섞였다. `app/EvidencePicker.tsx`가 이 부분을 맡는다. 기본 상태에서는 연결한 증거의 제목·출처·작성자, 원문 열기와 즉시 해제만 보인다. ‘증거 찾기’를 펼치면 수집한 기록을 검색하거나 출처로 좁힐 수 있으며 결과는 8개씩 표시된다. 선택 요약은 검색·출처·결과 페이지와 독립적으로 유지된다.

게시판의 공개 글은 이미 누적되어 있었지만, 사건 해결로 세계 시간이 앞으로 갈 때 최신 글이 첫 페이지를 모두 밀어냈다. `CommunityBoard`는 현재 목록에 반영한 공개 기록 ID를 보관하고 이후 도착한 글을 따로 센다. 플레이어가 ‘새 글 N개 반영’을 누르기 전에는 행, 사진첩, 댓글 목록, 검색, 분류, 정렬, 사진 필터와 페이지가 바뀌지 않는다. 반영할 때도 검색 조건과 페이지를 유지하며, 현재 정렬 기준에 맞게 새 글을 합친다.

## 추리와 저장 계약

- 증거의 원래 수집 순서를 유지한다. 질문의 내용, 정답 데이터, 정답 증거 ID는 검색·정렬에 사용하지 않는다. 질문별 추천, 자동 연결, 필수 근거 강조는 제공하지 않는다.
- 검색 대상은 제목, 기록 번호, 작성자, 본문, 댓글 작성자와 내용, 첨부 제목·열 이름·표 내용, 사진 설명이다. 출처 필터는 공개 주민 게시판과 받은 자료함을 구분한다.
- 최소 선택 수는 `Question.evidenceCount`, 최대 선택 수는 `evidenceLimit(question)`을 따른다. 고정 개수와 범위를 모두 표시한다. 최대에 도달해도 선택한 증거의 해제와 원문 읽기는 가능하다.
- `EvidencePicker`는 저장 요청을 직접 보내지 않는다. `Game.saveDraft`에 토글을 전달하며, 기존 원자적 최신 초안 업데이트·낙관적 표시·요청 병합·직렬 큐·실패 후 재시도를 계속 사용한다. 선택 결과가 검색에서 사라져도 초안은 바뀌지 않는다.
- 저장 중인 요청과 사용자 편집을 막아야 하는 요청의 기존 구분을 유지한다. 단순 초안 저장을 기다리는 동안 다음 체크가 가능하며, 해결·이동·초기화·수집 해제와 충돌할 수 있는 편집은 기존 `blocking` 값으로 막는다.
- 서버의 `Feedback.evidenceMessage`가 있으면 추리노트에 표시한다. 없는 응답에는 일반적인 재검토 문구를 사용한다.

## 게시판 세션 경계

- 새로 읽은 글, 증거 수집 여부 등 기존 글의 상태는 최신 진행 상태를 바로 따른다. 새로 반영할 공개 글의 ID만 목록 스냅샷으로 유지한다.
- 여러 단계의 새 글이 한꺼번에 대기해도 중복 없이 누적된다. 받은 자료함의 비공개 기록은 공개 목록이나 새 글 수에 포함하지 않는다.
- 현재 추리 사건을 이전 사건으로 바꿔도 세계 시간이나 이미 반영한 목록은 되돌아가지 않는다. 반영을 기다리는 새 글도 유지한다.
- 탭을 바꾸거나 도구 모달을 여닫아도 게시판을 재생성하지 않는다. 게임 시작과 성공한 초기화만 새 게시판 세션을 만든다. `boardSession`은 아직 시작하지 않은 게임을 다시 초기화하는 경우에도 필터를 확실히 비운다.
- 페이지를 새로 여는 경우에는 그때 접근 가능한 모든 공개 글을 초기 목록으로 보여 준다. 새 글 반영 여부는 읽기 화면의 임시 상태이며 서버 저장이나 브라우저 영구 저장을 추가하지 않았다.

## 접근성

- 공개/접기 버튼에 `aria-expanded`와 `aria-controls`를 제공한다. 검색·출처·결과·선택 목록·페이지 이동은 각자 이름을 가진다.
- 체크박스는 네이티브 컨트롤이다. 키보드 Tab/Space를 지원하며 Enter로 검색 목록을 펼칠 수 있다.
- 펼친 검색 영역에서 Escape를 누르면 해당 영역을 닫고 펼침 버튼으로 포커스를 돌려준다. 한글 입력 조합 중인 Escape는 가로채지 않는다.
- 결과 페이지를 바꾸면 결과 영역으로, 선택 요약에서 해제하면 인접 해제 버튼 또는 펼침 버튼으로 포커스를 보낸다. 새 글 반영 후에는 계속 존재하는 목록 제목으로 포커스를 보낸다.
- 연결 개수, 검색 결과 수, 새 글 도착/반영 결과를 상태 메시지로 알린다. 작은 화면에서는 선택 요약과 필터를 한 열로 배치한다.

## 검증과 인계

`tests/evidence-picker.test.tsx`는 선택 요약 유지, 모든 검색 대상, 출처 구분, 결과 분할, 즉시 토글/개수 제한, 키보드/포커스, 편집 차단 중 원문 읽기, 빈 수집함, 단계 상승 전후 목록 유지, 명시 반영, 여러 도착의 누적, 이전 사건 재방문, 실제 게임 초기화를 검증한다.

2026-09-08 최종 독립 실행에서 실제 게임 초기화를 포함한 UI 테스트 10개가 모두 통과했다. 전체 프로젝트 타입 검사(`npm run typecheck`)와 변경한 TSX/테스트 lint도 통과했다. 기존 지연 저장/실패 재시도/전체 8사건 테스트는 주 담당자가 변경된 접근성 계약에 맞게 갱신한다. 체크박스와 원문 읽기는 ‘증거 찾기’를 펼친 뒤 접근하고, 긴 수집 목록에서는 제목 검색을 사용한다. 접힌 상태의 연결 개수는 ‘연결한 증거’ 목록 또는 ‘근거 연결 해제’ 버튼으로 확인할 수 있다.

이 개발 작업에서는 새 패키지, API 호출, 데이터 스키마, 이미지, 브라우저 도구를 추가하지 않았다. 브라우저 검수·전체 빌드·배포는 주 담당자에게 인계한다.
