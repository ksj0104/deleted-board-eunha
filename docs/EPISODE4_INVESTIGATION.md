# 4화 조사 설계와 검증

2026-09-09. 직접 조사 조작을 명확하게 하고, 핵심 원본을 한꺼번에 전달하던 흐름을 4화부터 변경했다. 다른 사건의 자료 획득 방식은 이번 변경 범위에 포함하지 않는다.

## 원본 확보 흐름

아래 표는 개발 검증용 정답을 포함한다.

| 확보 자료 | 먼저 읽을 기록 | 조회 대상 |
| --- | --- | --- |
| 방문증 배정·이동 기록 4-3 | 출입 원본 2-3, 공사 안내 4-2 | V03 |
| 시설 잠금장치 점검표 4-4 | 이동 원본 4-3, 보행 연결도 4-1 | R09 |
| 개인 약속의 후속 쪽지 4-5 | 취소 안내 1-4, 처음 약속 1-5 | 우편함 |

회신은 기록을 찾을 출처와 조회 방법을 안내한다. 플레이어가 관련 기록을 읽고 식별 정보를 입력하면 해당 원본 하나만 첨부되며 원문 창이 열린다. 공백·대소문자·전각 입력을 정규화하되 다른 번호는 인정하지 않는다. 조회만으로 증거 수집이나 사건 해결을 완료하지 않는다.

미확보 원본은 자료함의 검색·첨부 수·미확인 수에서 제외하고 직접 열람과 수집도 차단한다. 조사대의 원문 버튼은 조회 창으로 이어지며 미리보기에 원문 항목을 표시하지 않는다. 조회 성공 후에는 이전 사건으로 이동해도 확보한 자료가 남는다. 조회와 회신은 게임 내부 동작이며 실제 외부에 요청하지 않는다.

## 직접 조사 화면

1. 보행 연결도와 시간순 인증 기록을 함께 표시한다. 네 기록 옆에서 장소를 선택하면 지도와 시간순 목록에 반영된다. 같은 장소에 중복 배치할 수 없으며 빈 선택으로 되돌릴 수 있다.
2. 공사 안내를 읽은 뒤 폐쇄 구간을 표시한다. 동문 인증과 실제 외부 이동을 구분할 수 있게 지도에 막힌 연결을 표시한다.
3. 시설 점검표로 시험을 준비하고 정상 전원·정전 재현을 선택한 뒤 내부 손잡이를 누른다. 정상 전원의 개방은 정전 시험으로 기록하지 않는다. 정전에서 개방한 관찰을 저장한다.

다음 행동 안내는 열람·입력·실험 여부만 사용한다. 장소 선택의 정오답은 미리 알려주지 않으며 잘못된 동선은 최종 확인에서 거부한다. 좁은 화면에서는 지도와 입력을 위아래로 배치하고 지도는 가로 스크롤로 확인한다.

## 저장 호환

진행 버전과 저장 키는 유지하며 선택 필드 `requested`를 추가한다. 이 필드가 없는 옛 저장에서 3화를 이미 해결했다면 기존에 전달했던 4화 원본 세 개를 유지한다. 아직 4화에 도달하지 않았다면 빈 확보 목록으로 시작해 이후 조회한다. 이미 읽거나 수집한 자료와 해결한 사건도 보존한다.

조회 저장 실패 시 성공 처리하거나 원문을 열지 않는다. 재시도와 새 클라이언트 복원, 손상된 저장 보존을 검증했다. 조사대의 기존 배치·완료·재플레이 저장 방식은 유지한다.

## 검증

- `npm test`: 110개 통과. 8화 전체 UI 캠페인에 원본 조회와 새 동선 선택·정전 시험을 포함한다.
- 새 검사: 미확보 자료의 검색·미리보기 차단, 열람 전 정답 추측 거부, 틀린 조회 거부, 순차 확보, 저장 실패·재시도·재접속, 이전 저장 호환.
- 조사대 검사: 원문 열람 조건, 오배치 후 재개, 정상 전원과 정전 실험 구분, 위치 중복 방지, 완료와 재플레이 보존.
- 타입·린트, Pages·Worker 빌드, 로컬 Pages 배포 파일 검사 통과.
- HTTP로 8화 진행·두 결말·저장 복원·세션 격리와 이미지 제공 통과.

UI 검사는 JSDOM이다. 사용 가능한 실제 브라우저가 없어 이번 변경의 Chrome 렌더링·터치 제스처는 직접 확인하지 못했다.
