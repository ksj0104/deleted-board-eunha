# 삭제된 게시판

은하아파트 커뮤니티의 보관 기록을 읽고, 증거를 연결해 사라진 주민과 게시판 폐쇄 계획을 조사하는 한국어 웹 추리 게임입니다.

8화 완결 캠페인 · 게시글 112개(기존 사건 기록 48개 + 일상 글 64개) · 에피소드별 이미지 프롤로그 8개 · 추리 문제 24개 · 두 가지 결말.

## 실행

Node.js 22.13 이상이 필요합니다. Windows PowerShell에서도 같은 명령으로 실행합니다.

```sh
npm ci
npm run dev
```

개발 서버가 출력하는 주소(기본 http://localhost:3000)를 엽니다. 개발용 D1 데이터베이스는 프로젝트의 `.wrangler` 아래에 저장되며 최초 접속 시 테이블을 생성합니다. 별도의 AI API 키나 유료 외부 API가 필요하지 않습니다.

```sh
npm test             # 전체 캠페인 엔진 + React 화면 상호작용 검증
npm run typecheck    # TypeScript 검사
npm run test:http    # 실행 중인 로컬 서버에서 전체 캠페인과 실제 저장소 검증
npm run build        # Cloudflare Worker 배포 빌드
```

`GAME_TEST_URL`을 지정하면 HTTP 검증 대상을 바꿀 수 있습니다. HTTP 검증은 별도의 새 익명 세션을 만들고 그 세션만 초기화합니다. 사용자의 게임 진행에는 접근하지 않습니다.

## 플레이

게시판 위 **이 세 가지를 밝혀 주세요**에 이번 사건의 세 질문이 계속 표시됩니다. 질문별 관찰 방향, 답 입력 여부, 선택한 근거 개수, 검증 후 재검토 상태를 확인할 수 있습니다. **먼저 읽을 글**에서 조사를 시작하거나 **질문 N 답과 근거 작성**으로 해당 답안에 바로 접근하세요. 화면 아래 **해결 목표**에서도 안내를 다시 열 수 있습니다.

글을 증거 보관함에 수집한 뒤에는 추리 노트에서 각 질문의 근거로 다시 선택해야 합니다. 세 질문의 답과 근거를 모두 준비해 **세 가설 검증하기**를 누르면 판정됩니다. 모든 일상 글을 읽거나 수집할 필요는 없습니다. **검증 준비됨**은 입력을 마쳤다는 의미이며, 검증을 통과한 질문만 **입증 완료**로 표시합니다.

처음에는 이미지와 함께 도입 이야기, 사건 상황, 이번에 밝혀야 할 세 가지 질문을 보여 줍니다. 각 사건에 처음 진입할 때 해당 프롤로그가 열리고, 게시판의 **도입 이야기 다시 보기**에서 재열람할 수 있습니다.

주민 게시판에는 사진, 일상 대화, 나눔 완료, 분실물 처리, 시설 문의의 후속 글이 이어집니다. 최신순·과거순·댓글순 정렬, 사진 글 필터, 페이지 탐색, 이전 보관본 함께 보기를 지원합니다. 조회수와 댓글은 창작된 보관 당시 기록이며 공감은 내 세션에 저장됩니다.

게시판 기록에서 글을 열고 중요한 기록의 **증거 수집**을 누릅니다. **추리 노트**에서 가설의 답과 지정된 개수의 근거를 선택하고 검증합니다. 숫자·시각 입력은 **입력 적용**으로 저장하고, 순서 문제는 위아래 버튼으로 정렬합니다. 오답은 재도전할 수 있으며 시도·시간 제한은 없습니다.

**증거 보관함**과 **추리 노트**는 게시판 위에 모달로 열립니다. 게시판 검색어·페이지를 유지하며, 추리 노트에서 근거의 **원문**을 바로 읽을 수 있습니다. 닫기나 Escape로 아래 창으로 돌아갑니다.

이전 사건의 증거도 계속 사용할 수 있습니다. **사건 목록**에서 해결한 사건으로 돌아가 해설을 읽을 수 있습니다. 8화를 해결하면 보고서 공개 범위를 선택하고 결말을 읽습니다. 다른 결말도 다시 볼 수 있습니다. **사건 기록 내려받기**는 해결 해설과 개인 메모를 UTF-8 텍스트로 내보냅니다.

## 저장과 개인정보

진행, 수집 증거, 읽음, 답안, 메모, 힌트, 결말은 D1에 저장합니다. 임의 UUID를 담은 HttpOnly / SameSite=Lax 쿠키가 익명 세션을 식별하며 HTTPS에서는 Secure를 설정합니다. 쿠키를 삭제하거나 다른 브라우저를 사용하면 새로운 게임으로 시작합니다. 계정 간 동기화 기능은 없습니다. 메모에는 개인 비밀정보를 쓰지 않는 편이 좋습니다.

저장 변경은 서버에서 검증하며 수정 버전을 비교해 동시 요청의 덮어쓰기를 막습니다. 정답·해설·결말 판정 모듈은 클라이언트 코드에서 실행하지 않습니다. 이 게임은 경쟁 또는 비밀 보호를 위한 시스템이 아니며 정적 콘텐츠를 의도적으로 분석하는 플레이어를 막지는 않습니다.

## 구조

- `lib/cases.ts`: 8화의 기록, 질문, 힌트
- `lib/community.ts`, `lib/stories.ts`: 64개 주민 글, 사진 정보, 에피소드별 도입 이야기
- `app/CommunityBoard.tsx`, `app/StoryPrologue.tsx`, `app/community.css`: 주민 게시판, 이미지 프롤로그, 모달 UI
- `lib/solutions.ts`: 서버 정답·근거·해설·결말
- `lib/game.ts`: 순차 해금, 정답·근거 검증, 상태 전이
- `app/Game.tsx`, `app/components.tsx`: 게임 화면과 상호작용
- `app/api/game/route.ts`, `db/store.ts`: 세션·요청 검증·D1 저장
- `db/schema.ts`, `drizzle/`: 데이터베이스 스키마와 배포 마이그레이션
- `tests/`: 독립 공략에 따른 엔진·화면·HTTP 전체 캠페인 검증
- `docs/PROJECT.md`: 범위와 사건 정본
- `docs/ASSETS.md`: 이미지 생성 출처와 프롬프트

인물·아파트·업체·사건과 서류는 모두 창작입니다. 보고서 공개와 제출은 게임 속 선택이며 실제 외부인에게 메시지를 보내지 않습니다.

## 배포

Sites의 vinext / Cloudflare Worker 구조를 유지합니다. `.openai/hosting.json`의 논리적 `DB` 바인딩에 실제 D1을 연결하고 `drizzle` 마이그레이션을 적용합니다. 배포 산출물은 `dist/server/index.js`, `dist/client`, `dist/.openai`입니다. 원본 프로젝트의 `main.py`와 IDE·Python 가상환경은 보존했으며 웹 게임에는 사용하지 않습니다.
