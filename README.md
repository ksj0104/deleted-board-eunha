# 삭제된 게시판

은하아파트 커뮤니티의 보관 기록을 읽고, 증거를 연결해 사라진 주민과 게시판 폐쇄 계획을 조사하는 한국어 웹 추리 게임입니다.

8화 완결 캠페인 · 기록 212개(공개 글 180개 + 비공개 자료 32개, 일상 글 164개 포함) · 이미지 프롤로그 8개 · 추리 문제 24개 · 두 가지 결말.

**[바로 플레이하기](https://ksj0104.github.io/deleted-board-eunha/)** · 로그인이나 API 키 없이 플레이하며, 진행은 각 플레이어의 브라우저에 자동 저장됩니다.

## 실행

Node.js 22.13 이상이 필요합니다. Windows PowerShell에서도 같은 명령으로 실행합니다.

```sh
npm ci
npm run dev:pages
```

개발 서버가 출력하는 주소를 엽니다. GitHub Pages와 같은 브라우저 저장 방식으로 실행하며 별도 서버, 데이터베이스, AI API 키가 필요하지 않습니다.

```sh
npm test             # 전체 캠페인 엔진 + React 화면 상호작용 검증
npm run typecheck    # TypeScript 검사
npm run build:pages  # GitHub Pages 정적 빌드 → dist-pages
npm run test:pages   # 하위 주소의 파일 제공, 실제 번들 실행과 저장 복원 검증
npm run preview:pages # 정적 빌드 미리 보기
```

기존 Cloudflare Worker 방식도 `npm run dev` / `npm run build`로 실행할 수 있습니다. 해당 방식의 `npm run test:http`는 별도 익명 세션으로 D1 저장을 검증하며, `GAME_TEST_URL`로 대상을 지정합니다.

## 플레이

중심 사건은 **연락이 끊긴 서윤에게 무슨 일이 있었고, 왜 그녀의 기록이 지워지고 있는가?**입니다. 플레이어는 서윤과 독서모임을 준비하던 주민입니다. 전출 안내를 본 뒤 본인의 최근 글을 확인하려고 계정을 추적하고, 그 글의 약속을 따라 마지막 소식을 물을 상대를 찾습니다. 각 화의 발견은 다음 조사를 시작하는 이유가 됩니다.

해결 목표는 화면 아래 **해결 목표** 버튼을 눌러 여는 모달에서만 표시합니다. 게시판 본문에는 목표 패널이나 조사 목표 문구를 표시하지 않습니다. 모달에는 중심 의문과 첫 기록을 읽을 이유가 나오며, 풀이에 충분한 관련 증거를 수집하면 **기록에서 생긴 의문**이 추가됩니다. 의문마다 확인해야 하는 이유와 전체 사건에의 기여를 설명합니다. **이 의문을 추리 노트에 정리**로 해당 답안에 접근하고, **관찰 방향 보기**는 필요할 때 펼칩니다. 모달을 닫아도 게시판의 검색과 페이지는 유지됩니다.

추리 노트의 문항은 해당 의문을 풀 수 있는 증거가 모이면 자동으로 나타납니다. 관련 없는 글의 개수나 단순 열람으로 열리지 않으며, 같은 사실을 입증하는 대체 자료 조합도 인정합니다. 노트에서는 답만 정리합니다. **내 추리 검증하기**가 수집한 증거에서 근거를 자동으로 연결하고 직접 조사 결과와 답을 확인합니다. 수집 해제로 미해결 문항이 숨겨져도 작성한 답은 보존하며, 다시 수집하면 함께 나타납니다.

이번 화의 세 추리가 모두 입증되면 다음 화를 엽니다. 모든 일상 글을 읽거나 수집할 필요는 없습니다. **검증 준비됨**은 답안·근거 수집·직접 조사를 마쳤다는 의미입니다. 검증 실패 시에는 전체 추리를 다시 검토하라는 공통 안내만 나오며, 문항별 정오답·맞힌 개수·자동 오답 힌트는 표시하지 않습니다. 준비 상태와 해결 목표의 추천도 정오답에 따라 달라지지 않습니다. 사건 전체를 해결하면 **입증 완료**와 해설을 표시합니다. 이전 버전에서 이미 해결한 사건의 문항과 해설은 계속 볼 수 있습니다.

각 사건에는 원문에서 단서를 직접 찾고 비교하는 조사대가 있습니다. 1화는 작성자 정보와 삭제 전 알림, 3화는 지급 전표, 4화는 인증 동선 지도와 정전 상태의 손잡이 시험, 5화는 보관 색인 조각과 봉인, 6화는 게시 변경 이력과 삭제 대상, 7화는 발신 인증과 진술, 8화는 보고서의 사실·미확정·보호 정보를 대조합니다. 자료의 항목을 눌러 펼치고 대응하는 칸에 놓은 뒤 조사 결과를 확인하세요. 성공하면 대조한 원문을 증거 보관함에 함께 수집합니다. 키보드·터치·드래그와 배치 자동 저장을 지원합니다. 상세 설계는 [직접 조사와 자동 추리 노트](docs/DIRECT_INVESTIGATION.md)에 기록했습니다.

각 사건에 처음 진입하면 이미지와 함께 이전 발견, 이번 사건의 중심 의문, 조사를 이어갈 이유를 담은 프롤로그가 열립니다. 개별 정답 문제를 먼저 나열하지 않습니다. 게시판의 **도입 이야기 다시 보기**에서 재열람할 수 있습니다.

2화 **엇갈린 기록**에서는 **관리동 정문 작동 점검 기록**과 **C2 보관 화면 · 3월 18일**을 각각 살펴봅니다. CCTV의 **점검 중 표지가 있는 장면** 세 장과 **회색 외투 장면** 두 장을 전환하고, 이미지를 누르면 확대해서 볼 수 있습니다. 카메라의 시간 차이는 도입이나 점검 문서에서 미리 알려주지 않습니다.

두 원문을 읽으면 **기록 대조 열기**로 영상과 센서의 시간선을 함께 놓을 수 있습니다. 같은 문 움직임을 찾아 영상 줄을 드래그하거나 좌우 버튼·슬라이더로 조절한 뒤 **대조 확인**을 누르세요. 세 동작을 대조하면 그 결과가 저장되고 사건 영상의 **원본 시각 / 보정 시각** 전환이 열립니다. 시간선 위치는 자동 저장되며 실패 시 다시 저장할 수 있습니다. **다시 대조하기**는 기존 확인 결과를 보존합니다. 시각 추리는 두 원문, 사건 순서는 그 원문들과 출입·정전 근거까지 함께 연결합니다.

3화의 **E-318 세금계산서 원본 확인**은 실제 생성한 세금계산서와 업체 회신 공문 두 페이지로, **공동관리비 이체 확인**은 은행 확인서 이미지로 열립니다. 문서를 누르면 확대해 금액·계좌·발신 정보를 비교할 수 있습니다. 지급 전표 조사대는 **금액 비교 → 두 이체 → 업체·승인자** 순서로 원문 항목과 입력 칸을 나란히 보여 줍니다. 목록에서 항목을 한 번 고르면 바로 기입되고 차액은 자동 계산됩니다. 공문 이미지를 같은 화면에서 펼쳐 확대할 수 있으며, 미열람 자료는 원문을 먼저 열어야 선택할 수 있습니다. 기존 배치·완료·저장 재시도는 유지합니다.

3화 **받은 자료함 → 파쇄함에서 회수한 결산 수정 쪽지**에서 문서 복원 미니게임을 플레이합니다. 1화의 파쇄기 목격담을 따라 입주자 감사가 봉인한 폐지에서 종이 조각 열 개를 회수했습니다. 생성한 손글씨 원본 이미지를 실제로 세로 10줄로 잘랐습니다. 조각을 드래그하거나 두 조각을 차례로 눌러 자리를 바꾸고, 글줄·표 선·접힌 흔적이 이어지면 **복원 확인**을 누릅니다. 완성하면 쪽지 원본을 확대해 읽을 수 있습니다. 키보드 Tab·Enter와 모바일 터치 선택도 지원합니다. **복원 요령**은 관찰 방법만 안내합니다. 이전 6조각 저장은 10조각 배치로 변환하며, 완료 이력과 기존 증거·답안·메모는 유지합니다. 이미지·크롭 좌표·프롬프트는 [3화 문서 이미지](docs/EPISODE3_IMAGES.md)에 기록했습니다.

복원 전에는 쪽지 전문과 근거 수집이 잠겨 있고, 완료하면 공개 결산의 변경 내용과 승인자의 회신이 드러납니다. **증거 수집** 후 기존 3화·8화 추리의 근거로 사용할 수 있습니다. 배치는 즉시 움직이고 뒤에서 저장하며, 창을 닫거나 재접속하면 저장된 자리부터 이어갑니다. 저장 실패 시 **배치 다시 저장**으로 재시도합니다. 이전 버전에서 이미 읽은 쪽지·수집·답안은 유지하고 **조각 다시 맞춰보기**로 미니게임을 체험할 수 있습니다. 다시 맞추기는 기존 증거를 되돌리지 않습니다.

글·자료 열기, 창 닫기, 단서 배치·해제, 증거 수집, 힌트와 추리 검증에 짧은 효과음이 나옵니다. 화면 위의 **효과음 켜짐/꺼짐**으로 바로 끄거나 켜고, **음량**에서 크기를 조절하고 미리 들어볼 수 있습니다. 기본 음량은 35%이며 설정은 이 브라우저에 보관합니다. 음원은 브라우저에서 생성하고 첫 조작 뒤에만 재생합니다. 빠른 조작은 재생 간격과 동시 재생 수를 제한하며, 메모 입력·자동 저장·숨겨진 탭은 조용히 처리합니다.

주민 게시판은 하나의 공간으로 유지됩니다. 게임 속 날짜가 흐르면 **새 글 N개 반영** 알림이 도착합니다. 알림을 누르기 전에는 읽던 목록이 그대로 남고, 누르면 검색·분류·정렬·페이지를 유지하면서 새 글을 더합니다. 공개 장부·지도처럼 예전부터 있던 자료는 해당 추리 단계에 도달하기 전에도 읽을 수 있습니다. 이전 사건을 다시 열어도 게시판의 시간이 되돌아가지 않습니다. 사진·일상 대화·시설 문의의 후속 글, 최신순·과거순·댓글순 정렬, 사진 필터와 페이지 탐색을 지원합니다.

추가한 주민 글 100개 중 80개는 사건 전의 생활 기록이며, 시작 시 **97개 공개 글**을 검색할 수 있습니다. 후속 글 20개는 게임 속 날짜에 따라 추가됩니다. 공지, 생활 질문, 거래, 민원, 설문, 공동구매, 분실물과 후기 속에 인물·장소·물건이 반복 등장합니다. 게시판 검색에 **동문 공사**처럼 단어를 띄어 쓰면 모든 단어를 포함한 글만 찾습니다. 제목·본문·댓글·첨부표를 함께 검색하고, 결과에서 일치한 문맥과 강조된 단어를 확인할 수 있습니다.

**받은 자료함**에는 조사 결과에 이어지는 회신과 자료 인계가 누적됩니다. CCTV 캡처·이체 확인서·개인 쪽지·관리자 원본은 공개 게시글로 섞이지 않고 출처가 있는 첨부파일로 도착합니다. 원문 작성 시각과 자료를 받은 시각은 별도로 표시합니다. 해결 후 **도착한 회신 확인하기**를 누르면 다음 이야기를 읽고 받은 자료함으로 이어집니다. 게시판의 검색·분류·페이지는 자료함을 오가거나 다음 단계로 진행해도 유지됩니다.

4화는 회신에 원본을 모두 첨부하지 않습니다. 이전 출입 기록과 게시판 공사 안내에서 조회 대상을 찾아 **방문증 이동 원본**을 요청하고, 이동 기록과 보행 연결도를 대조해 **시설 점검표**를 확보합니다. 후속 쪽지도 처음 약속을 주고받은 상대를 찾아 조회합니다. 확보 전 원본은 자료함 검색이나 조사대 미리보기에 나타나지 않습니다. 직접 조사는 **지도와 기록 연결 → 폐쇄 구간 표시 → 정전 시험**의 세 단계이며, 기록 옆에서 장소를 고르면 지도에 바로 반영됩니다. 기존 저장에서 이미 4화에 도착해 받은 자료는 유지합니다. [4화 조사 설계와 검증](docs/EPISODE4_INVESTIGATION.md).

게시판 기록에서 글을 열고 중요한 기록의 **증거 수집**을 누릅니다. **추리 노트**에 나타난 문항에 가설의 답을 작성하고 검증합니다. 숫자·시각 입력은 **입력 적용**으로 저장하고, 순서 문제는 위아래 버튼으로 정렬합니다. 오답은 재도전할 수 있으며 시도·시간 제한은 없습니다.

답안은 즉시 화면에 반영되고 뒤에서 저장됩니다. 같은 질문의 대기 중 변경은 마지막 상태로 모아 보내며, 늦게 도착한 저장 응답이 최신 답안을 되돌리지 않습니다. 검증은 마지막 저장이 끝난 뒤 실행합니다. 실패한 답안은 창을 닫아도 유지하며 **추리 다시 저장**으로 재시도합니다. 저장되지 않은 답안이 있을 때 페이지를 떠나려 하면 브라우저가 확인을 요청합니다.

이전 버전의 해결 이력·메모·초안은 유지됩니다. 미해결 사건은 새 직접 조사를 완료하고 필요한 기록을 수집하여 이어서 풀 수 있습니다. 이미 해결한 사건은 조사대를 다시 체험해도 해결 이력을 취소하지 않습니다.

**증거 보관함**과 **추리 노트**는 게시판 위에 모달로 열립니다. 게시판 검색어·페이지를 유지하며, 조사대에서 자료의 **원문**을 바로 읽을 수 있습니다. 증거 보관함은 최근 수집한 자료를 위에 표시합니다. 닫기나 Escape로 아래 창으로 돌아갑니다.

이전 사건의 증거도 계속 사용할 수 있습니다. **사건 목록**에서 해결한 사건으로 돌아가 해설을 읽을 수 있습니다. 8화를 해결하면 보고서 공개 범위를 선택하고 결말을 읽습니다. 다른 결말도 다시 볼 수 있습니다. **사건 기록 내려받기**는 해결 해설과 개인 메모를 UTF-8 텍스트로 내보냅니다.

## 플레이테스트 반영

게시판의 현재 검색어·분류·사진 필터를 필터 칩으로 표시합니다. 다음 사건의 새 글이 필터에 가려졌다면 개수를 알리고 **필터 해제하고 새 글 보기**로 최신 목록을 엽니다. 조사 중 검색·페이지를 유지하는 기존 동작도 사용할 수 있습니다.

시각은 **HH:MM / HH:MM:SS**를 허용하며 `20:14`와 `20:14:00`을 같은 시각으로 판정합니다. 형식 오류는 입력란에서 안내하고, 초가 다른 시각을 같은 답으로 처리하지 않습니다. 4화 원본 조회에는 먼저 확인할 원문과 바로 열기 버튼을 표시합니다. 원문 확인 전에는 조회할 수 없고, 입력한 번호는 원문을 다녀와도 유지됩니다.

추리 노트는 검증 전에 필요한 직접 조사와 이동 버튼을 표시합니다. 5~8화 조사판은 읽은 자료의 항목을 펼쳐 두고 **연결할 위치** 선택으로 바로 배치합니다. 파쇄 문서는 10조각을 유지하며 전체 보기·확대 보기와 교환할 자리 선택을 제공합니다. 프롤로그는 첫 문단과 두 가지 할 일을 먼저 보여 줍니다. 엔딩의 **사건 목록으로**는 원문·추리 노트 등 열린 창을 함께 정리합니다.

허위 전출 공지의 목적을 보여 주는 감사 로그 메모를 추가하고, 7화 인물 대사와 입증 범위에 관한 기록자 메모를 분리했습니다. 보조 글씨·조사 입력의 가독성, 첨부 수량 읽기, 효과음 미리 듣기의 화면 상태도 보완했습니다. [플레이테스트 반영 내역](docs/PLAYTEST_REFINEMENTS.md).

## 저장과 개인정보

GitHub Pages에서는 진행, 수집 증거, 읽음, 공감, 프롤로그 열람, 답안, 메모, 힌트와 결말을 브라우저의 `localStorage`에 저장합니다. 키는 `eunha.deleted-board.progress.v1`이며, 같은 GitHub 계정의 다른 프로젝트 데이터와 구분됩니다. 새로고침하거나 창을 닫아도 같은 주소·브라우저·프로필로 돌아오면 이어서 플레이합니다. 사이트 데이터를 삭제하거나 다른 기기·브라우저로 접속하면 새 게임으로 시작합니다. 시크릿 모드의 기록은 해당 세션이 끝나면 사라지며 계정 동기화는 없습니다.

추리 판정과 저장은 브라우저 안에서 처리하며 게임 API를 호출하지 않습니다. Chrome에서는 Web Locks로 여러 탭의 저장을 순서대로 처리하고 매 요청마다 최신 기록을 읽습니다. 저장 공간 부족·저장 차단·손상된 기록은 오류로 안내하고 기존 기록을 임의로 초기화하지 않습니다. **처음부터 다시 시작**은 이 게임의 기록만 초기화합니다.

Pages 공개 소스와 정적 파일에는 정답 판정도 포함됩니다. 경쟁이나 정답 비밀 유지를 위한 시스템은 아닙니다. 기존 Sites/Worker 주소의 D1 진행은 출처와 저장 방식이 달라 Pages 주소로 자동 이전되지 않습니다. Worker 방식은 기존 익명 세션 쿠키와 D1 저장을 계속 사용합니다.

## 배포

GitHub 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 설정합니다. `main`에 푸시하면 `.github/workflows/pages.yml`이 검사와 테스트를 수행한 뒤 `dist-pages`를 배포합니다. 이후 같은 저장소에 푸시하면 공개 게임도 자동 갱신됩니다. 상대 자산 경로를 사용하므로 프로젝트 하위 주소에서도 이미지와 CSS/JS를 불러옵니다. 공유 링크 메타데이터는 `GITHUB_REPOSITORY`에서 생성합니다.

기존 Sites의 vinext / Cloudflare Worker 빌드도 유지합니다. 해당 배포는 `.openai/hosting.json`의 논리적 `DB` 바인딩과 D1 마이그레이션을 사용하고, 산출물은 `dist/server/index.js`, `dist/client`, `dist/.openai`입니다. 원본 프로젝트의 `main.py`와 IDE·Python 가상환경은 웹 게임에 사용하지 않습니다.
